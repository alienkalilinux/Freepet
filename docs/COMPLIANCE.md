разработчиков и проверяющих.

> заключение юриста. Перед публикацией в рабочей среде покажите документы
> специалисту по законодательству Республики Казахстан и заполните реальные

## Ключевые технические решения

### Согласия

- Версия согласий: `CONSENT_VERSION = "2026-11-09"` (`frontend/src/lib/legal.ts`).
- При регистрации сервер сохраняет версию согласия и время (`User.consent_version`,
  `User.consent_at`), а также отдельно маркетинговое согласие
  (`User.marketing_consent`, `User.marketing_consent_at`).
- Маркетинговое согласие необязательно и по умолчанию выключено.
- Согласие на внешние карты хранится в браузере (`fripet-consent-v1`) и может быть
  отозвано в любой момент через «Настройки cookie».

### Cookie

- Категории: необходимые (всегда) и внешние карты (по согласию).
- Аналитических, рекламных и маркетинговых cookie нет.
- Баннер не блокирует сайт: необходимые функции работают без согласия на карты.

### Данные

- Публичные ответы API не раскрывают email/телефон владельца анкеты.
- Экспорт данных: `GET /api/account/export` возвращает JSON.
- Удаление: `DELETE /api/account` с подтверждением пароля; связанные данные
  удаляются, отдельные записи сохраняются только в пределах законных сроков.
- Запросы без доступа к аккаунту принимаются на `NEXT_PUBLIC_PRIVACY_EMAIL`.

### Изображения

- При загрузке фото животного выполняется автоматическая проверка через
  Hugging Face Inference API. Передаётся только файл изображения, без данных
  аккаунта. Это раскрыто в политике и документе о сторонних сервисах.

## Что осталось сделать перед публикацией

1. **Заполнить реквизиты оператора** — переменные `NEXT_PUBLIC_LEGAL_*`
   (наименование, форма, БИН/ИИН, адрес, контакты). Без них страница
   `/legal/requisites` честно показывает «не указано».
2. **Проверить юридические тексты у юриста** по законодательству Республики
   Казахстан, включая Закон № 94-V «О персональных данных и их защите».
3. **Настроить рабочую почту** для `NEXT_PUBLIC_PRIVACY_EMAIL` и
   `NEXT_PUBLIC_SUPPORT_EMAIL`, чтобы запросы на удаление и жалобы не терялись.
4. **Проверить сторонние сервисы** по [THIRD_PARTY_SERVICES.md](./THIRD_PARTY_SERVICES.md):
   договоры, регион обработки, ключи API.
5. **Провести независимый аудит доступности** (WCAG 2.1 AA /
   ГОСТ Р 52872-2019) и устранить найденные барьеры.
6. **Проверить сценарии вручную**: регистрация, добавление питомца, заявка,
   экспорт, отписка, удаление аккаунта, отзыв согласия на карту.

## Ограничения

- Сайт не принимает платежи, не хранит данные карт, не ведёт рассылки и не
  показывает отзывы. Поэтому соответствующие разделы документов описывают
  отсутствие функций, а не выдуманные правила.
- Автоматическая модерация не гарантирует выявление всех нарушений; окончательное
  решение по жалобам принимает человек.
- Полное соответствие WCAG 2.1 AA не заявляется до независимой проверки всех
  страниц и сценариев.
